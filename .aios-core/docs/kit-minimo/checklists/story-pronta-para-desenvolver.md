# Checklist · Story pronta para desenvolver

Use este checklist antes de começar a implementação. A ideia é verificar se a story está clara o suficiente para alguém desenvolver sem caça ao tesouro.

## 1. Objetivo e contexto
- [ ] A story deixa claro **o que** deve ser construído
- [ ] O benefício de negócio ou operacional está explícito
- [ ] A relação com o épico ou fluxo maior está descrita
- [ ] Dependências anteriores estão nomeadas
- [ ] O resultado esperado é específico, não vago

## 2. Direção técnica mínima
- [ ] Arquivos ou áreas principais do código foram indicados
- [ ] Tecnologias ou decisões não óbvias foram citadas
- [ ] Interfaces, endpoints ou contratos relevantes aparecem na story
- [ ] Modelos de dados / estruturas afetadas foram referenciados
- [ ] Variáveis de ambiente ou configurações especiais foram listadas, se houver
- [ ] Exceções ao padrão normal do projeto foram anotadas

## 3. Referências úteis
- [ ] Links ou caminhos apontam para seções específicas, não para documentos inteiros sem contexto
- [ ] Informações críticas não ficaram só nas referências; há um resumo na própria story
- [ ] O motivo de cada referência existir está claro
- [ ] O formato de referências está consistente

## 4. Autossuficiência
- [ ] A story é entendível sem abrir dez arquivos antes
- [ ] Termos de domínio importantes foram explicados
- [ ] Premissas implícitas foram tornadas explícitas
- [ ] Casos de erro ou edge cases relevantes foram lembrados

## 5. Testabilidade
- [ ] Há indicação de como testar
- [ ] Cenários principais de teste estão listados
- [ ] Critérios de aceite são verificáveis
- [ ] Existe validação manual ou automatizada prevista

## Resultado
- **READY**: dá para implementar com segurança razoável
- **NEEDS REVISION**: faltam detalhes, mas é corrigível
- **BLOCKED**: falta contexto externo essencial

## Pergunta final
- [ ] Se eu recebesse esta story agora, eu conseguiria implementá-la sem alto risco de retrabalho?
