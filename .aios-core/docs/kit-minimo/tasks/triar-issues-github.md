# Task · Triar issues do GitHub

## Quando usar
Quando o backlog de issues ficou grande, confuso ou misturado, e você precisa decidir o que entra agora, depois ou nunca.

## Objetivo
Transformar uma fila bruta de issues em uma visão priorizada e acionável.

## Passos
1. Levante as issues abertas.
2. Para cada issue, classifique ao menos:
   - tipo: bug, feature, docs, chore, security, enhancement;
   - severidade: P0, P1, P2, P3;
   - esforço: XS, S, M, L;
   - urgência: agora, próxima sprint, depois, backlog.
3. Marque quick wins: itens pequenos com valor alto ou risco removido rapidamente.
4. Separe com destaque:
   - bugs críticos;
   - segurança;
   - itens que bloqueiam outras entregas;
   - itens que parecem stale.
5. Monte um relatório curto com quatro grupos:
   - **NOW**
   - **NEXT**
   - **SOON**
   - **BACKLOG**
6. Feche ou rebaixe itens claramente obsoletos, se houver decisão para isso.

## Saída esperada
Uma lista priorizada, escaneável e fácil de transformar em ação.

## Formato sugerido
- `#123 [BUG/P1] descrição curta — S`
- `#456 [SECURITY/P0] descrição curta — M`

## Regra prática
Triagem não é só ordenar por opinião; é reduzir ruído e destacar o que realmente merece atenção primeiro.
